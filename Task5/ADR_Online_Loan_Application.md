## Контекст и проблема

После успешного запуска **MVP депозитов** (Task 3, Q2-Q3 2026) банк "Стандарт" расширяет онлайн-функционал на **кредитные продукты**. Срок: **в течение 1 года после MVP** (Q1-Q4 2027).

**Текущие проблемы:**
- Заявки только в отделениях (высокий барьер входа)
- Batch-процессы АБС ↔ Кредитный конвейер (раз в сутки)
- Среднее время одобрения: 3-5 дней
- Нет онлайн-скоринга

**Цели:**
- Увеличить конверсию на 25%
- Same-day обработка для предодобренных клиентов
- Привлечь молодую аудиторию (25-40 лет)

## Функциональные требования (Use Cases)

### UC-1: Новый клиент подаёт заявку с сайта

1. Заполняет калькулятор (сумма, срок, цель)
2. Видит предварительный расчёт
3. Заполняет анкету (ФИО, паспорт, доход)
4. Прикрепляет документы (опционально)
5. Система запускает онлайн-скоринг через БКИ
6. Получает предварительное решение (одобрено/на рассмотрении/отказ)
7. Получает СМС с номером заявки

### UC-2: Существующий клиент из интернет-банка

1. Видит предодобренные предложения
2. Заполняет заявку с упрощённым скорингом
3. Подтверждает СМС-кодом (2FA)
4. Получает решение same-day

### UC-3: Сотрудник продолжает работу с онлайн-заявкой

1. Клиент приходит в отделение
2. Сотрудник находит заявку по номеру
3. Проверяет документы и формирует договор
4. Средства зачисляются

### UC-4: Андеррайтер обрабатывает в Кредитном конвейере

1. Открывает заявку в Camunda
2. Просматривает скоринг и документы
3. Одобряет/отклоняет/запрашивает допданные
4. Клиент получает СМС о решении

## Нефункциональные требования

### Performance

- **P-1:** Расчёт ставки < 500 мс
- **P-2:** Онлайн-скоринг < 5 сек
- **P-3:** Same-day обработка предодобренных

### Reliability

- **R-1:** Uptime 99.9%
- **R-2:** Circuit Breaker для БКИ
- **R-3:** Дедупликация заявок

### Security

- **SEC-1:** TLS 1.3
- **SEC-2:** 2FA через СМС
- **SEC-3:** Шифрование паспортов (AES-256)
- **SEC-4:** Rate Limiting (10 заявок/час с IP)

## Альтернативы

### Альтернатива 1: Полная автоматизация без андеррайтеров

**Плюсы:**
- Мгновенное одобрение (< 1 мин)
- Снижение затрат
- 24/7 работа

**Минусы:**
- Риск фрода
- Compliance риски (требования ЦБ)
- Негибкость для индивидуальных случаев

**Вердикт:** Отклонено для MVP. Возможно для микрокредитов < 100 000 руб в v2.1

### Альтернатива 2: Синхронная интеграция с Кредитным конвейером

**Плюсы:**
- Простота (меньше компонентов)
- Мгновенная консистентность

**Минусы:**
- Tight coupling
- Нет retry при сбоях
- Блокирующие вызовы

**Вердикт:** Отклонено. Kafka предпочтительнее для надёжности

### Альтернатива 3: Хранение документов в PostgreSQL

**Плюсы:**
- Не нужна доп. инфраструктура
- Транзакционность

**Минусы:**
- Раздувает БД (паспорт = 2-5 МБ)
- Медленнее чтение
- Дороже хранение

**Вердикт:** Отклонено. S3/MinIO — индустриальный стандарт

### Альтернатива 4: Service Mesh (Istio)

**Плюсы:**
- Централизованное управление трафиком
- Встроенный мониторинг
- Circuit breakers из коробки

**Минусы:**
- Сложность инфраструктуры
- Требует Kubernetes expertise
- Overhead на обучение команды

**Вердикт:** Отклонено для MVP. Рассмотреть в v3.0 при масштабировании

## Ограничения решения

### Технические ограничения

| Ограничение | Описание | Митигация |
|-------------|----------|-----------|
| Batch АБС ↔ Кредитный конвейер | Обмен раз в сутки, нельзя ускорить | Добавить REST API для онлайн-заявок, сохранить batch для совместимости |
| Система скоринга перегружена 9-18 | Нельзя добавлять нагрузку | Кеш результатов (TTL 24ч), запуск тяжёлых скорингов ночью |
| АБС масштабируется только вертикально | Oracle DB, монолит | Асинхронная интеграция через Kafka для защиты |
| Интернет-банк несовместим с Kafka | Legacy технологии | REST Proxy для Kafka или HTTP-адаптер |
| БКИ может быть недоступно | Внешнее API, SLA 99% | Circuit Breaker + fallback на ручное рассмотрение |

### Бизнес-ограничения

| Ограничение | Описание |
|-------------|----------|
| Scope MVP | Только потребительские кредиты (не авто, не ипотека) |
| Идентификация | Новый клиент ОБЯЗАН прийти в отделение (115-ФЗ) |
| Лимит суммы | Автоскоринг только для кредитов < 500 000 руб |
| Команда разработки | Ограничена, нужна приоритизация |

### Регуляторные ограничения

| Требование | Источник |
|------------|----------|
| Личная идентификация для новых клиентов | 115-ФЗ "О противодействии легализации доходов" |
| Хранение персданных в РФ | 152-ФЗ "О персональных данных" |
| Ручной контроль крупных кредитов | Положение ЦБ РФ 254-П |
| Шифрование финансовых данных | Стандарт PCI DSS |

### Архитектурные ограничения

**Что НЕ делаем в MVP:**
- Полная автоматизация одобрения
- Мобильное приложение (только веб)
- Биометрическая идентификация
- Open Banking API (для получения данных из других банков)
- Real-time скоринг для всех заявок

**Технический долг:**
- После MVP нужна миграция интернет-банка на микросервисы
- Нужен API в Кредитном конвейере (сейчас только UI)
- Требуется оптимизация системы скоринга для онлайн-режима
